# Capacity desk: fixed preflight comparison protocol

Freeze this protocol, task, harness and evaluator before either generation session.
The question is whether explicitly prompting the existing composition preflight
improves the first checked implementation, final correctness, or effort for one
fresh complex task. This is one exploratory pair, not a causal efficacy estimate.

Both arms receive the same six-warehouse brief, immutable DESIGN.md/data/rules,
14px minimum, three CSS viewports (1000×900, 1600×1000, 390×844), engine 0.10.0,
shared guide, browser action adapter, reporting tools, and first/final preservation.
The baseline review skill omits exactly its two preflight-invocation paragraphs;
the treatment keeps them. All other assistance, including access to the same
preflight file and composition companion, remains available. Measure actual reads;
incidental baseline use would dilute this prompt-level contrast and must be reported.
This does not compare all of old Viewrule against all of new Viewrule.

Run baseline then preflight once each in fresh ephemeral account-authenticated
Codex CLI sessions: gpt-6-astra, ultra, eight minutes and 600,000 provider-reported
cumulative tokens including cached input. Tokens may cross the cap at the next
usage notification; report actual totals. No extra retry or replacement run for a
failed session. Do not feed independent evaluator results to either session.
Record requested/returned model, CLI/browser versions, rerouting/errors, stopping
reason, protected-file hashes and all configured check calls. The workspace sandbox
controls writes; isolation from other readable files is an instruction boundary.

The first check snapshots the source before returning findings. This is the first
checked implementation, not necessarily the first edit or rendered attempt. Preserve
each check's source/report/captures, plus final source, an external final check,
and first/final independent browser observations. Compare each arm's first and final
saved runs under the unchanged contract; do not compare measurements across different
ports or claim identical authorship histories. Preserve identical images explicitly.

The independent evaluator checks exact decision fields, initial desktop fit and
mobile horizontal fit, six chart sample-coordinate series on a shared declared
scale, keyboard disclosure, combined filters/reset, projected sorting, hidden
selection persistence, blocked selection guards, exact row/batch action identities,
data preservation, and page errors. Geometric checks do not prove semantic chart
truth; coordinate/visibility checks also have limits (occlusion and paint details).
Inspect original captures separately and label this author review as unblinded.

Before sessions: validate a separately authored legal control and mutations removing
a capacity denominator and enabling a blocked batch. Require the legal control to
pass both configured and independent checks. Record which known faults are detected
by which layer; a configured pass on an unsafe action demonstrates the boundary,
not a successful UI. Probe queued requests, docs paths and browser interactions.
Do not retune any rule, task, control or evaluator after seeing generation outcomes.

Report first/final configured findings and independent failure categories by viewport;
identify discovered misses and false alarms concretely rather than giving a general
recall/precision score from two samples. Distinguish first-check defects, subsequent
agent checks, post-first source revisions, and externally added final validation.
Report generation elapsed time, input/cached/output/reasoning tokens, and raw total.
Pricing is not instrumented: no inferred dollar cost. Shared preparation, verification
and inspection are outside generation timing, so no end-to-end efficiency claim.
No blind human rating or production automatic-skill-selection claim is possible.
Preserve no-benefit, negative and incomplete outcomes with the same prominence.
